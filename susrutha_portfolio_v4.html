Projects

Work I am proud of.

From trial monitoring dashboards to AI-powered food label readers, these are builds where I owned the data end to end.

01
Alzheimer's Disease Clinical Trial Monitoring Dashboard
Simulated multicenter trial database with real-time R Shiny monitoring of enrollment, visit compliance, and open queries.
R ShinyPostgreSQLtestthat
Problem: Trial monitoring requires real-time visibility into enrollment, visit compliance, and data quality across multiple sites. Static reports create lag and teams miss issues until data lock.

Built a simulated multicenter Alzheimer's trial database in PostgreSQL. Developed an R Shiny dashboard showing enrollment vs. target, visit window compliance, missing eCRFs, and open queries, filterable by site and arm. Wrote edit checks in R for out-of-window visits and implausible score changes. Generated parameterized progress reports with R Markdown.

Result: Fully reproducible monitoring system with traceable validation tests in testthat and GitHub documentation so every output can be audited end to end.
R Shinydplyrggplot2R MarkdownPostgreSQLPythontestthatGitHub
02
AI-Assisted Clinical Data QC Utility Toolkit
Shared R and Python QC utilities with Claude API for drafting check code and cross-language CI validation via GitHub Actions.
Claude APIPythonRGitHub Actions
Problem: QC checks in research trials are written manually, inconsistently, and rarely documented in a way auditors can trace back to their specification.

Built shared R and Python utilities for duplicate detection, range checks, date logic, and cross-form consistency checks driven by a YAML specification. Used the Claude API to draft check code from plain-language specs, with every generated check reviewed by hand and logged. Added a cross-language consistency test that fails the GitHub Actions build whenever R and Python outputs disagree on the same dataset.

Result: Reusable toolkit with AI-assisted development, cross-language validation, and written guidelines covering data privacy, validation, and documentation.
PythonpytestRtestthatClaude APIGitHub ActionsYAML
03
Customer Segmentation for Targeted Marketing
K-Means clustering on 500,000+ transactions to identify actionable customer segments. Research paper published from CSU East Bay.
Pythonscikit-learnPCA
Problem: Businesses rely on blanket marketing campaigns even when customer purchasing behavior clearly clusters into distinct groups with different needs.

Applied K-Means clustering to over 500,000 transactions from a UK e-commerce dataset. Built a full pipeline: removed missing values and duplicates, derived 12 behavioral features, applied IQR-based outlier removal, StandardScaler normalization, PCA for dimensionality reduction, then K-Means to identify three customer segments.

Result: Three actionable segments identified: high-value customers (premium offers), mid-tier (retention and upselling), and low-engagement (re-engagement campaigns). Research paper published from CSUEB. Team with Ashish Padavala.
PythonPandasscikit-learnKMeansPCAMatplotlibJupyter
04
Accessible Food Label Reader OCR Pipeline
End-to-end data pipeline for fine-tuning a vision-language model to read food labels for visually impaired users.
PythonQwen2-VLOCR
Problem: Visually impaired users cannot easily read nutritional information on food packaging. Existing OCR tools fail on real-world label images with poor lighting, warped text, and varied fonts.

Built and owned the full data pipeline: sourced raw label images, designed augmentation workflows for rotation, brightness, and noise variance, structured dataset folders for training and validation, and wrote ETL scripts to prepare clean inputs for model fine-tuning. The team then fine-tuned a Qwen2-VL 2B vision-language model for food label object detection, using regex extraction to surface nutritional data as structured text.

Result: End-to-end OCR pipeline from raw images to structured nutritional output, with a reproducible data augmentation suite and a fine-tuned vision-language model. Team with Ashish Padavala.
PythonQwen2-VLOCRData AugmentationETLRegexJupyter

How I work

Things I actually believe.

Not a methodology. Just how I end up working.

01 If I cannot trace a number back to its source, it does not go in the report.Provenance first.
02 A fix is not done when the bug disappears. It is done when there is a test that would have caught it.Future me counts.
03 R and Python. Both. If they agree, great. If they do not, that is the real finding.Cross-check everything.
04 AI is a tool, not a shortcut. Every generated output gets reviewed, tested, and logged before it ships.Responsible by default.
05 Good documentation is a form of respect for the people who come after you.Write it down now.
06 The best question in a data review is "where did this number come from?" I ask it before anyone else gets the chance.Ask early.
